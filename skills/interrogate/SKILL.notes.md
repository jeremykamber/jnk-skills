# jnk-interrogate — notes

Private notes for the human. The agent never sees this file.

**What:** Interrogate the user on their understanding of a target — a repo, a feature, a subsystem — across thirteen coverage areas. Socratic chains, verified against the code; a six-step teaching ladder when the user gaps; coverage kept visible so it ends.

**When:** the user wants to own the understanding — before an interview or a design review, after a major implementation, or as a periodic "am I still actually the engineer here?" check. Never mandatory; a mode, not a beat.

**Why:** AI leverage silently becomes AI dependence when understanding lives only in the model. Interrogate is the deliberate reversal: the model asks, the user answers, and a wrong answer is the point — that's where the learning happens. The explain-back closes every gap, so the model's explanation alone never counts as learning.

**Fits:** the comprehension counterpart to grill (decisions) and understand (the agent's model-building before a change). Feeds nothing — it is the user's own. May hand durable facts to `docs/external/` and unresolved decisions to grill.

**The architecture it completes:** Design — what should exist? Implement — build it. Interrogate — do I understand it? Grill — are the decisions sound? Verify — does it work? Debrief — what did we learn?

**Refs:** the Socratic method (question chains that expose assumptions), the layered-understanding loop (teach in layers; tutor not authority), the teach-back (if you can't explain it simply, you don't understand it), Matt Pocock's grilling (mechanism lineage).
