# Pedagogy catalog

The instructional operations the operating loop chooses between. Every question and every
piece of feedback has a diagnostic or learning purpose — never filler.

## Question catalog

| Purpose | Examples |
|---|---|
| Retrieve | "What are the three steps?" / "Without looking, reconstruct the idea." |
| Discriminate | "Why does method A work here but not method B?" |
| Expose misconception | "If this variable doubles, does the output necessarily double?" |
| Generate | "Give me an example where this principle applies." / "Give me a counterexample." / "Don't repeat the steps — tell me why this method was appropriate." |
| Transfer | "Solve a case where the surface features are completely different." / "Which of these three problems need the principle — and which just look like they do?" |
| Calibrate | "How confident are you, 0-100?" |

Never ask "What do you think?" / "Why?" / "Can you explain?" without a specific purpose.

## Feedback taxonomy

Seven distinct learner states require seven distinct interventions:

1. **Correct answer, correct reasoning** → confirm in one line, raise difficulty
2. **Correct answer, wrong reasoning** → correct the reasoning, not the outcome
3. **Correct answer, no reasoning** → probe: "How did you decide?"
4. **Lucky guess** → re-test with a variation
5. **Misconception** → name it, give a targeted contrast, re-probe
6. **Careless execution error** → point it out, have them redo it carefully
7. **Knowledge gap** → teach the missing piece, starting at minimum assistance

Bad: "Almost! Great job! You're on the right track 😊"
Good: "Your conclusion is correct, but the reason isn't. You said X causes Y because X happens
first. That's temporal order, not evidence of causation. Try again using the idea of a control
group."

Timing: give feedback right after the retrieval attempt, before the next attempt. Retrieval
practice plus feedback beats testing without feedback.

## Scaffolding ladder (minimum assistance)

When the learner says "I don't know" and has relevant prior knowledge, do not answer — escalate
one rung at a time, only while they are still stuck:

1. "That's okay. Give me the first thing you *do* know."
2. One clue — not the answer.
3. "Which of these two approaches seems more plausible?"
4. "Exactly. Now finish it."
5. Only then: the solution.

The objective is the **minimum assistance necessary**, which is a different objective from
"be helpful." If the gap is a genuine lack of schema — there is nothing to retrieve from —
skip the ladder and teach the missing piece minimally; escalation without schema just
frustrates.

## Explanation layers

Start shallow; go deeper only as far as the current bottleneck requires. Never dump the full
account upfront.

1. Intuition — "A derivative tells you how quickly something is changing *right now*."
2. Concrete example — "If your position changes from 10m to 20m over a second, that's an
   average rate. The derivative asks what your speed is at one particular instant."
3. Representation — graph, diagram, simulation.
4. Formal definition — the equation or precise statement.
5. Consequences — what follows from it.
6. Edge cases — where it breaks.
7. Formalism / proof — only when asked or needed.

## Vocabulary protocol

Three tiers per term: **must recognize**, **must use**, **not needed yet**. Do not introduce
five synonyms for one concept.

Establish canonical language: "I'm going to call this *conditional probability*. You may
encounter other phrasings; we'll use this one."

When a technical term is required, pair it with plain English:

> **Technical term:** prior probability
> **Plain English:** what you believed before seeing the new evidence.

Remove the translation as the learner advances. The target is "What's the prior?" — not
"What's that thing that means what you believed beforehand?"

## Representation sequence

Move between representations instead of memorizing one verbal form:
words → example → diagram → equation → simulation → prediction → explanation.

Example (acceleration): describe it → look at a velocity-time graph → predict what happens →
animate it → write the equation → calculate → explain the graph to someone else.

Choose the sequence by subject. The goal is connections between representations.

## Tools

Use a tool only when it changes what cognition is possible — never because it is cool.

| Tool | Use when |
|---|---|
| Visualization | Spatial or temporal relationships matter |
| Simulation | The learner must manipulate variables and observe consequences |
| Calculator / code | Computation would consume cognitive resources needed for the concept |
| Diagramming | The structure of relationships is the thing being learned |
| External sources | Evidence, competing explanations, primary literature, current information |
| Flashcards | Discrete facts only — never the universal mechanism |
| Writing | Generating an explanation is itself the learning activity |

The tool is subordinate to the learning objective.

## Errors as teaching material

A wrong answer is information. Identify the misconception and generate a targeted contrast:

> "You're treating *where a plant gets its materials* as the same thing as *where it gets
> usable energy*. Let's separate those two ideas. Which supplies the carbon atoms that end up
> in glucose?"

Erroneous examples (having the learner find and fix errors) can help, but only with enough
prior knowledge and clear framing — they can confuse novices. Do not apply "productive
failure" blindly; see [evidence.md](evidence.md).

## Desirable difficulties

The session should sometimes feel harder than it needs to. Learners often *prefer* blocked
practice and believe they are learning more from it while actually learning less. When you
introduce difficulty on purpose — retrieval, spacing, interleaving, generation, variation,
explanation, comparison, transfer — say so in advance.

**Never stack difficulties.** Apply one at a time. Cognitive effort must target the learning
process, not be consumed by unnecessary complexity — stacking retrieval + interleaving +
generation + transfer onto a novice is harmful, not helpful.
